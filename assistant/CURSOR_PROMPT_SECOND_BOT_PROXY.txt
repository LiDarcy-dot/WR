Промпт для Cursor (второй бот) — только Telegram-прокси, ничего лишнего
======================================================================

Скопируй всё ниже в Cursor Agent чат второго бота.

---

Задача: аккуратно добавить поддержку прокси только для Telegram API у этого бота. Ничего больше не рефакторить.

Контекст:
- На VPS в NL уже крутится SOCKS5 (microsocks) на порту 1080.
- Системный VPN на Windows не используем: госуслуги/банки/браузер должны ходить напрямую.
- Прокси нужен ТОЛЬКО процессу бота → Telegram Bot API / getUpdates.
- Тот же прокси уже использует другой ассистент через env `TELEGRAM_PROXY`.

Сделай минимальный diff:

1) Конфиг
- Добавь переменную окружения `TELEGRAM_PROXY` (опциональная строка).
- Пример: `socks5://tgproxy:PASSWORD@31.15.16.97:1080`
- Пустое значение = работать как сейчас, без прокси.
- Не коммить секреты/пароли в git. В `.env.example` только закомментированный пример.

2) Подключение прокси
- Если проект на python-telegram-bot v20+/v21+/v22:
  при создании Application:
  `Application.builder().token(...).proxy(url).get_updates_proxy(url).build()`
  когда url не пустой.
- Если aiogram 3: прокси в session (AiohttpSession(proxy=...)) или актуальный способ для версии проекта.
- Если другой стек — используй штатный способ библиотеки, не городить свой http-клиент.

3) Зависимости
- Для PTB SOCKS: `python-telegram-bot[socks]` и при необходимости `httpx[socks]` / `PySocks`.
- Поставь только недостающее, не ломай текущие pins/lockfile без нужды.

4) Логи
- При старте если прокси задан: одна строка в лог с МАСКОЙ пароля
  (`socks5://tgproxy:***@host:port`), без пароля в открытом виде.

5) Не делать
- Не менять бизнес-логику, хендлеры, БД, деплой, имя бота.
- Не включать системный proxy/env HTTP_PROXY глобально для всего процесса, если можно ограничить только Telegram-клиентом.
- Не трогать браузерную автоматизацию и прочие сервисы.
- Не удалять существующие настройки.

6) Проверка
- Кратко напиши: какой файл изменён и что добавить в `.env`.
- Как перезапустить бота.
- Ожидание: бот отвечает в Telegram при выключенном full-tunnel VPN.

Значение для `.env` пользователь подставит сам (строка `TELEGRAM_PROXY=...` с VPS). В код пароль не хардкодить.

---
Конец промпта.
